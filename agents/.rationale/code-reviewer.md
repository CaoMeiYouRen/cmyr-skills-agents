# Code Reviewer（agent）— 设计理由（Why）

> 面向维护者。执行审查角色时不需要读本文件；只有重构、合并、降级或删除该 agent 时才需要。
> 角色边界看 [../code-reviewer.agent.md](../code-reviewer.agent.md)，审查规则看 `code-reviewer` / `security-guardian` skill。

## 1. 存在理由

- 为审查动作提供**独立的角色视角与上下文隔离**：审查者不与被审代码同处一个实现上下文，减少"作者替自己辩护"。
- 把审查的触发从"用户记得要求 review"变成"场景自动触发一个专门角色"。
- 没有它时的可观察损失：审查退化为实现者自检，或与实现混在同一上下文里，独立性下降。

## 2. 设计哲学

第一性原理：**审查是一个需要独立身份的阶段，而不是实现流程里的一个步骤。**

由此派生：

- 角色只保留职责、边界与接棒关系；完整审查规则下沉到 skill，避免双写。
- 默认停在 review，不直接改代码——审查与实现分离。
- 作为 Gate 结论的出口，而不是意见的收集者。

## 3. 关键假设

- 存在可调用的 `code-reviewer` / `security-guardian` skill。
- 存在 diff 或明确审查范围可供分析。
- 调用方（用户或 `full-stack-master`）会声明 `audit-depth` 与证据摘要。

## 4. 失效场景与删除判据

当以下条件**同时**成立时，本 agent 应降级为默认助手的一个模式或直接删除：

1. 审查已完全由自动化门禁 + 单个技能覆盖，不再需要独立的角色身份与上下文隔离。
2. 编排层（`full-stack-master`）能直接调用审查 skill 并保证独立性，独立 agent 成为冗余。
3. 审查规则已收敛到 skill，agent 文件本身不再承载任何不可替代信息。

降级/删除前必须确认：审查的独立性、Gate 出口、证据要求都有替代载体。

## 5. 能力替代 vs 不可推断

- **能力替代型**：通用"要独立审查""要覆盖安全与性能"的提醒。
- **不可推断型**：与 `code-reviewer` / `security-guardian` skill 的集成关系、与 `full-stack-master` 的接棒边界、audit-depth 的调用方声明约定、默认不改代码的职责约束。

## 6. 项目覆盖锚点

| 参数 | 默认值 | 项目覆盖位置 |
| :--- | :--- | :--- |
| diff 规模阈值 | 10 文件 / 800 行新增 | 项目 `AGENTS.md` |
| 审查规则与时间盒 | 见 `code-reviewer` skill | 项目 `AGENTS.md` 或 `docs/standards/*` |
| 强制参考文档 | `AGENTS.md` / `README.md` / `SECURITY.md` | 项目 `AGENTS.md` |

优先级：**技能/agent 默认 < 项目覆盖 < 会话覆盖**。

## 7. 关键取舍

- 用角色隔离换取审查独立性，代价是多一次上下文切换。
- 不承担需求规划、功能开发与完整测试设计主责，避免角色膨胀为万能执行器。
