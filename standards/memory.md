# 经验沉淀与蒸馏（memory）

> 任务过程的临时发现不自动变资产：先落任务态，再按阈值蒸馏到项目文档或技能 references。
>
> 载体路径与蒸馏阈值是现用形态（2/4 项目：caomei-ui、dependfix）；其他项目按同样职责换路径即可。`≥20 条触发蒸馏`与 Session 收尾流程以 `skills/full-stack-master` 的 Session 协议为准，本文件不重述。

## 1 载体分工

| 载体 | 跨度 | 放什么 |
| :--- | :--- | :--- |
| 待办 / roadmap | 天到周 | 阶段目标、进行中事项、验收点 |
| `.session/current-task.yaml` | 小时到会话 | 当前进度、阻塞点、失败计数与推理模式（**失败与模式的权威来源**） |
| `.session/wisdom.md` | 跨 session | 值得复用的发现，尚未定稿 |
| `docs/design/governance/experience-archive.md` | 长期 | 已蒸馏的经验条目（失败模式、验证方法、平台坑） |
| 技能 `references/` 或项目规范 | 长期 | 需要被下次执行直接加载的判定规则 |

- 失败计数与推理模式以 `current-task.yaml` 为准；运行快照文件只存状态，不重复当权威。
- mem0 一类跨项目记忆只放「跨仓库可复用的偏好与决策」，不写密钥、不写一次性细节。

## 2 蒸馏触发

满足任一即执行：

| 条件 | 阈值 |
| :--- | :--- |
| 时间 | 距上次蒸馏 > 30 天 |
| 阶段收口 | 当前阶段归档时 |
| 用户触发 | 「蒸馏 wisdom」「整理一下」 |

## 3 去向判定

- 影响下次执行的判定规则 → 技能 `references/`（跨项目）或项目 `AGENTS.md`（项目参数）。
- 事故复盘与失败模式 → 经验档案，按主题分节，不按时间堆叠。
- 一次性结论、临时路径、个人环境细节 → 不蒸馏。

## 4 写入纪律（踩过的坑）

- `.session/current-task.yaml` 是**YAML 形态的纯文本**：条目值以 `**` 开头会被当成别名指示符，长句里的半角冒号加空格会触发嵌套映射；按文本读取，不要用 YAML 解析器解析，顶层键要唯一。
- 追加条目先 `grep -n '^## '` 确认分区边界：直接 `cat >>` 会落进最后一个分区（曾把活跃条目写进「已蒸馏」段，计数脚本静默不再命中）。
- 蒸馏后删除已迁移的临时条目，避免两处并存；保留指针，不保留副本。
