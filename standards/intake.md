# 外部技能准入与库存治理（intake）

> 外部技能是**参考来源或调用入口**，不是项目库存。项目内技能的主定义始终在 `.github/skills/`。

## 1 准入规则

1. 来源必须可追溯，且不得伪装成项目内部定义（不能放在 `.github/skills`、`.claude/skills` 里冒充本地技能）。
2. 引入前先核来源与内容安全：投毒面（提示注入、执行任意命令、读取凭据）与供应链来源（作者、仓库活跃度、是否与官方文档一致）必须过一遍，不能只看它能用。
3. 只作参考 / 入口 / 能力补充，不复制为长期镜像。
4. 与项目规范冲突时，以项目规范（`AGENTS.md`、`docs/standards/*`）为准，不因外部技能的说法放宽。
5. 同一外部技能被连续依赖 ≥ 3 次、且需要补项目特化约束时，评估转内部化，而不是长期靠人工记忆维持。
6. 外部技能缺失、描述过时或与当前事实不符时，降级到官方文档 / 事实源复核，不带着旧结论继续用。

## 2 唯一事实源

- 结构化清单以项目内的 registry（如 `.github/external-skills-registry.json`）为准。
- 说明文档（本文件的项目版）只负责可读性；两者不一致时先修 JSON，再同步文档，视为治理漂移。

registry 至少记录：ID、适用范围、来源路径、同步地址、更新频率、失效处理、转内部化门槛。

## 3 库存变更同步

新增、合并或弃用一个技能 / 角色时，同一次改动里同步：

- [ ] 索引（`AGENTS.md` 或等价入口）
- [ ] 分发清单（L0 / 模板 / 安装脚本）
- [ ] 平台镜像（按脚本重新生成，不手工改）
- [ ] 引用它的文档与 agent 文件
- [ ] registry 与说明文档（涉及外部技能时）

弃用不等于删除：保留文件、移出索引与分发清单、写明替代与移除条件；确认无回归后再物理删除。

## 4 与技能创建的分工

- 「怎么造一个技能」在 `skills/skill-creator`；本文件只管「外部能力能不能进来、进来后算什么」。
- 「这一类需求该用哪个技能」在技能索引与 `skills/find-skills` / 编排角色；本文件不做能力检索。
