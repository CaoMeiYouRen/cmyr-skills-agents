# 角色矩阵与阶段去重（roles）

> 本文件只定义「谁在哪一阶段主责、什么时候不能并行」，不定义各角色的工作流（那在技能里）。

## 1 两层分工

| 层 | 载体 | 内容 |
| :--- | :--- | :--- |
| 角色 | agent 文件 | 身份、边界、输入输出、交接点、禁区 |
| 能力 | skill | 执行流程、判定规则、检查清单 |

角色文件**不复制**技能正文；需要某项能力时引用对应技能。角色收壳：agent 只保留「谁、什么时候上、交给谁」，规则下沉到 skill 或本目录。

## 2 阶段主责（P/D/A/V/T/F）

| 阶段 | 主责 | 不替代 |
| :--- | :--- | :--- |
| P 规划 | 需求 / 产品角色 | 其他角色只提供上下文，不替代准入判断 |
| D 实现 | 实现主责（默认编排角色统筹） | 边界稳定前不拆给多个实现角色 |
| A 审计 | 审计角色（独立上下文） | 开发者自检不等于审计通过 |
| V 验证 | 浏览器 / UI 验证角色 | 测试角色不替代可视验证 |
| T 测试 | 测试角色 | 审计只审测试质量，不替代测试设计 |
| F 交付 | 编排 / 实现角色（含单次提交） | 文档角色负责回写，但不回写未确认的产品结论 |

**阶段去重规则**：同一事项在同一时点只能有一个主责；需要并行时，并行的是**只读取证**，写入与结论仍由主责统一收口。跨阶段改动（如实现中发现问题）按「先记录、再评估、不静默扩写」处理。

## 3 默认推荐路径

- 单点改动、单文件问答、纯文档修订：用一个技能即可，不启动全流程编排。
- 涉及三个阶段以上，或需要审计门禁：走编排角色，由它按阶段分派。
- 只有出现新的独立角色需求（跨阶段接棒、治理职责）时才新增 agent；可复用工作流一律沉为 skill。

## 4 主定义、镜像与库存治理

- `.github/agents/`、`.github/skills/` 是主定义；`.claude/`、`.opencode/`、`.agents/` 是发现入口的兼容镜像，由脚本生成/校验，不手工维护。
- 镜像必须与主定义同名、同库存、同职责边界；不得独立发明另一套角色体系。
- 任何库存变更（新增、合并、弃用）都要同步：索引（`AGENTS.md`）、平台镜像、分发清单（L0 / 模板）、引用它的文档。
- 弃用的角色与技能保留文件、移出索引与分发清单，并写明替代与移除条件。

## 5 Agent 还是 Skill

判据见 `AGENTS.md` 的「角色收壳原则」与 `skills/skill-creator`，本文件只给结论：需要身份 + 边界 + 接棒关系 → agent；需要可复用流程或判定 → skill；两者都要时 agent 只写身份与交接。
