# Super Search — 设计理由（Why）

> 面向维护者。调用本技能时不需要读本文件；只有重构、合并、降级或删除时才需要。
> 触发看 `SKILL.md` 的 `description`，执行流程看 `SKILL.md` 正文；本文件只回答"为什么存在、何时该消失"。

## 1. 存在理由

- 把"凭训练记忆直接回答"替换为"每条事实都可追溯到本次会话抓取过的 URL"。
- 对抗两类系统性错误：幻觉（编造不存在的事实）与过时（训练数据停留在过去）。
- 没有它时的可观察损失：报告里的数字/版本/价格凭记忆估算，无法核实，误导决策。

## 2. 设计哲学

两条第一性原理：

1. **搜索引擎所知道、所能找到的，一定比本地或模型记忆更多。**
2. **遇到无法解决的问题时优先搜索——因为你不是唯一遇到这个问题的人。**

由此派生：

- 搜索是默认动作，不是兜底动作；训练数据不能当作事实来源。
- 多源交叉验证：一致才标注确认，矛盾必须回溯一手来源，孤立声明只能待验证。
- 对抗性审查：主动搜索反面证据，不因"查起来麻烦"跳过时效性与真实性审查。
- 有 Fast Path：90% 的搜索不必走完整 9 步，按需匹配深度，避免为流程而流程。

## 3. 关键假设

- 有可用的搜索与抓取工具（含 curl 降级路径）。
- 目标主题至少存在一个可访问的一手 / 官方来源。
- 网络可达，且工具失败时可降级到其他工具或本地验证手段。

若工具全部不可用或主题无可查来源，应显式声明结论受限，而不是用记忆填补。

## 4. 失效场景与删除判据

当以下条件**同时**成立时，本技能可降级为一条轻量铁律（"必须引用可追溯来源"）：

1. 模型原生具备可靠的实时检索、来源追溯与事实核查能力，且成为默认行为。
2. 工具降级、缓存、多语言信源优先级等工程细节已被通用平台能力吸收。

降级/删除前必须确认：领域化查证手段（GitHub API 精确 metrics、CSDN 封禁、信源分层、对抗审查触发条件）有替代载体。这些属不可推断项，若其依赖的项目/工具约定仍存在则必须保留。

## 5. 能力替代 vs 不可推断

- **能力替代型（随模型变强应删减）**：通用"要多源交叉验证""注意信息时效性"的提醒，以及基础搜索关键词扩展的通用建议。
- **不可推断型（必须保留）**：GitHub API 的精确查证维度、CSDN 无条件排除、信源分层权重与多语言原始语言优先级、工具降级顺序与 curl 回退、缓存 TTL、报告模板选择规则、输出路径的 8 处同步点。

## 6. 项目覆盖锚点

| 参数 | 默认值 | 项目覆盖位置 |
| :--- | :--- | :--- |
| 报告输出目录 | `./research-output/` | 项目 `AGENTS.md` |
| 缓存目录 | `~/.super-search-cache/` | 项目 `AGENTS.md` |
| 报告模板 | 见 `references/report-templates.md` | 项目 `AGENTS.md`（数据多时链到 references） |
| 交付方式 | 长内容走附件 | 项目 `AGENTS.md` |

优先级：**技能默认 < 项目覆盖 < 会话覆盖**。项目交付规范与技能冲突时以项目为准。

## 7. 关键取舍

- 深度调研耗时高，因此保留 Fast Path，在准确性与速度之间按主题风险取舍。
- 强制"每条声明附来源链接"会增加输出成本，换来源可核实与可复现。
- 不适用于纯概念解释类问题（不需要联网查证），此时应拆成一次轻量搜索或直接回答并声明依据。
