# 项目覆盖层（Project Overlay）约定

当同一个技能 / agent 被多个项目复用、但各项目又有不同需求时，用**覆盖层**承载差异：通用部分只在上游 `cmyr-skills-agents` 维护一次，项目差异写入项目内的独立文件。

这是"承认项目差异，同时提高复用率"的落地机制。

---

## 1. 三层结构

| 层 | 载体 | 维护方 | 读者 | 加载时机 |
| :--- | :--- | :--- | :--- | :--- |
| 核心（what/how） | 上游 `skills/<name>/SKILL.md`、`agents/<name>.agent.md` | 上游 | 执行者 | 每次 |
| Why | 上游 `references/rationale.md`、`agents/.rationale/<name>.md` | 上游 | 维护者 | 重构 / 弃用 / 删除时 |
| 项目覆盖层 | 项目 `.ai/overrides/skills/<name>.md`、`.ai/overrides/agents/<name>.md` | 项目 | 执行者 | 每次（存在时） |

## 2. 存放位置

- 项目根目录 `.ai/overrides/{skills,agents}/<name>.md`。
- 与 `.ai/manifest.json` 同域，但**不纳入快照哈希**——它是项目自有内容，不是上游生成物。
- 不放在 `.github/skills`、`.github/agents` 下，避免被平台加载器当成同名能力扫描。

## 3. 组合语义

- 默认 **additive**（追加）：覆盖文件中的规则追加到核心之后执行。
- 需要替换默认值时，必须显式写成 `覆盖：<锚点> → <新值>`，不允许隐式覆盖。
- 优先级：**会话 > 项目覆盖 > 核心默认**。
- 覆盖文件不存在时，能力按核心默认独立工作——覆盖永远是可选的。

## 4. 文件结构（只写差异）

```markdown
# <name> 项目覆盖

## 追加必查项
- …

## 覆盖默认参数
- <锚点> = <项目值>

## 追加反模式 / 项目禁用
- …

## 项目适配说明
- 链到 `docs/standards/*`，不在此抄写规范正文
```

## 5. 职责边界

| 内容 | 归属 |
| :--- | :--- |
| 对单个能力的追加规则 / 检查 | `.ai/overrides/**` |
| 对单个能力默认参数的覆盖 | `.ai/overrides/**`（或项目 `AGENTS.md`） |
| 跨能力的全局参数（阈值、命令、路径） | 项目 `AGENTS.md` |
| 项目规范本身（长篇、跨能力） | `docs/standards/*` |

## 6. 反退化约束

- 覆盖文件**只写差异**，不得抄写核心已有条款（同"规范单点声明"原则）；否则覆盖层会变成第二事实源。
- **膨胀阈值**：覆盖文件持续增长 = 上游抽象不足的信号。此时应向 `CaoMeiYouRen/cmyr-skills-agents` 提 issue，把通用部分上移到核心，而不是让覆盖层无限增长。
- 覆盖内容若被证明是多个项目共需，应回贡上游，成为核心的一部分。

## 7. 与分发的配合

- 核心能力通过 L0 快照分发到项目 `.github/skills|agents`（见 `cmyr-template-cli` 的 `ct ai-update`）。
- 项目内**通用改动先改上游**；紧急情况下可临时改覆盖层，但必须同时向上游提 issue，上游合入后收敛回核心。
- 覆盖层不参与快照校验，因此"项目改了快照却没回贡上游"由哈希校验拦下，"项目改了覆盖层"则是允许的正常操作。
