# references/rationale.md 模板（技能 / agent 通用）

面向**维护者**，不是执行者。调用技能或 agent 时不需要读它；只有在重构、拆分、合并、降级或删除时才需要加载。

本文件不参与触发（触发看 `description`），不重复工作流，也不抄写项目规范——只回答"为什么要有它，以及什么时候它该消失"。

存放位置：

- 技能：`skills/<name>/references/rationale.md`
- agent：`agents/.rationale/<name>.md`（放在点目录，避免被 `.claude/agents`、`.opencode/agents` 等加载器当成 subagent 扫描）

---

## 1. 存在理由

- 它替代了哪种人工步骤或重复劳动？
- 没有它时，会发生什么可观察的损失？

## 2. 设计哲学

- 用一句话写出第一性原理。
- 为什么这样设计，而不是另一种做法？

## 3. 关键假设

- 它成立依赖哪些前提（模型能力、工具可用性、项目规范是否存在）？
- 每条前提被破坏时会触发什么后果？

## 4. 失效场景与删除判据

- 哪些假设一旦不成立，本技能就应被删除、合并或降级？
- 删除或降级前，需要确认哪些替代方案与迁移动作？

## 5. 能力替代 vs 不可推断

- **能力替代型**：属于"教模型通用做法"的内容，会随模型变强而冗余，甚至产生有害的过度约束，应优先删减。
- **不可推断型**：项目阈值、路径、工具降级顺序、踩坑经验等模型无法自行推导的事实，必须保留。
- 逐项标注本技能中哪些属于哪一类，作为未来"减法"的依据。

## 6. 项目覆盖锚点

- 哪些参数是项目可变的（阈值、路径、门禁、输出格式）？
- 项目覆盖写在哪里？默认读项目 `AGENTS.md`；数据量大时由 `AGENTS.md` 一行链到 `docs/standards/*`。
- 无覆盖时的默认值是什么？
- 优先级固定为：技能默认 < 项目覆盖 < 会话覆盖。

## 7. 关键取舍

- 明确放弃了什么，换取了什么（例如：速度 vs 严格度、通用性 vs 项目贴合度）。
- 什么场景下本技能不适用，应显式跳过而不是勉强执行。
