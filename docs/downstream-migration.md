# 下游项目 AI 资产迁移参考方案

> 面向使用 `cmyr-skills-agents` 的项目，说明如何把项目内 fork 的技能 / agent 迁移到「核心 + 覆盖层」模式，提高跨项目复用率。
>
> 迁移由**项目自身**执行；本文件是参考方案，不是自动脚本。

---

## 1. 目标模型

| 层 | 载体 | 维护方 |
| :--- | :--- | :--- |
| 核心（what/how） | 项目 `.github/skills`、`.github/agents`（来自上游的 L0 快照） | 上游 |
| Why | 上游 `references/rationale.md`、`agents/.rationale/<name>.md` | 上游 |
| 项目覆盖层 | 项目 `.ai/overrides/{skills,agents}/<name>.md` | 项目 |
| 项目规范 | 项目 `AGENTS.md`（全局参数）、`docs/standards/*`（规范正文） | 项目 |

原则：**通用部分只在上游维护一次；项目差异只写进覆盖层或项目规范，不写回 fork 正文。**

---

## 2. 迁移前先分类

对项目内每个与上游同名的技能 / agent，判定其内容关系（先与**上游历史基线**比对，避免把上游演进误判为项目特化）：

| 判定 | 含义 | 处理 |
| :--- | :--- | :--- |
| **C 字节一致** | 与上游逐字节相同 | 直接改为快照；差异归零 |
| **S 结构同源** | 章节骨架相同，仅标记 / 措辞 / 少量注记不同 | 注记移入覆盖层，改为快照 |
| **M 部分同源** | 主结构保留但插入了项目内容 | 项目内容移入覆盖层 / `docs/standards`，核心按上游对齐 |
| **W 重写** | 章节结构与上游明显不同 | **不做同步**：先评估"重写回上游骨架 + 覆盖层"的收益，收益不足则保持项目自有并登记理由 |
| **P 项目自有** | 上游无对应 | 保留，纳入规范冗余扫描监控 |
| **deprecated** | 与同名 skill 能力重叠、已无独立价值 | 保留文件、移出索引与分发清单，写明替代与移除条件 |

判定方法：`sha256sum` 比字节；`grep '^#{1,3} '` 比章节结构。

---

## 3. 迁移步骤（逐能力）

1. **内容二分**：把项目 fork 正文拆成"通用协议"与"项目特化"。
2. **通用协议**确认已在上游 canonical 中；缺失的**向 `cmyr-skills-agents` 提 issue**，由上游补充。
3. **项目特化**写入 `.ai/overrides/{skills,agents}/<name>.md`（只写差异）；属于规范正文的写入 `docs/standards/*`。
4. **改为快照**：项目内不再手工维护该能力，改由 L0 快照提供（`ct ai-update`，或与上游一致的同步方式）。
5. **记录**：在 `.ai/manifest.json` 记录来源 commit 与哈希；把校验接入 `ai:check`。
6. **验证**：跑项目全套门禁；确认无项目规则丢失；确认覆盖层生效。

> W 类先做第 1 步评估：只有当消除的重复条款足够多时才重写；否则保持项目自有。

---

## 4. 覆盖层写法

位置：`.ai/overrides/skills/<name>.md`、`.ai/overrides/agents/<name>.md`。

```markdown
# <name> 项目覆盖

## 追加必查项
- 浮层 / portal 改动必须核验宿主页面稳定性（见 docs/standards/testing.md）

## 覆盖默认参数
- diff 规模阈值 = 8 文件 / 500 行

## 追加反模式 / 项目禁用
- …

## 项目适配说明
- 链到 docs/standards/*，不抄规范正文
```

规则：
- 只写差异，不抄写核心已有条款；
- 需要替换时显式写 `覆盖：<锚点> → <新值>`；
- 优先级：会话 > 项目覆盖 > 核心默认；
- 覆盖层持续膨胀 = 上游抽象不足 → 提 issue 上移通用部分。

---

## 5. 分发与校验

- 若项目使用 `cmyr-template-cli`：`ct ai-update` 重新取 L0 快照并更新 `.ai/manifest.json`。
- 校验：`.ai/manifest.json` 的哈希与项目 `.github/skills|agents` 逐文件比对，不一致即失败。
- 覆盖层**不纳入**快照哈希（它是项目自有）。

> 规范上游 `standards/` 目前不参与 L0 自动分发：项目按需复制到 `docs/standards/` 或与自有规范合并，见 [standards/README.md](../standards/README.md) §4。

---

## 6. 上游反馈（GitHub issue）

- 通道：`CaoMeiYouRen/cmyr-skills-agents` 提 issue。
- 内容：能力名 / 类型（新增·修改·删除）/ 现状与痛点 / 建议改动 / 影响项目 / 验收标准。
- 流程：上游合入 → 项目重新取快照 → 删除临时覆盖内容。
- 紧急情况：允许临时写在覆盖层，但必须同时提 issue。

---

## 7. 验收清单

- [ ] 应迁移能力的项目 fork 已改为快照，项目规则全部落在覆盖层 / `docs/standards`。
- [ ] 覆盖层只含差异，无抄写核心条款。
- [ ] `.ai/manifest.json` 存在且哈希校验通过；篡改快照能被拦下。
- [ ] 项目门禁（`ai:check`、规范冗余扫描等）全绿。
- [ ] W 类能力已明确结论（重写 / 保持自有）并登记理由。
- [ ] deprecated 能力已移出索引与分发清单，写明替代与移除条件。

---

## 8. 常见误区

- **按名字同步**：同名不同内容，直接覆盖会丢项目规则。
- **对比当前上游**：会把上游演进算成项目差异；应以历史基线比对。
- **把通用改进留在 fork**：应回贡上游，否则复用率不会提升。
- **覆盖层无限增长**：应上移通用部分，而不是持续加覆盖。
